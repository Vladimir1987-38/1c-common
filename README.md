# Общие инструменты проектов 1С

Библиотека правил, навыков и скриптов для команды. Конкретные информационные системы в примерах обозначаются как «Проекты».

Начните с [инструкции разработчику](инструкции%20разработчику/README.md): расположение папок, подключение проекта, обязательные файлы и рабочие команды. [Подготовка к GitHub](инструкции%20разработчику/Публикация%20в%20GitHub.md) описывает состав публикации и локальные настройки.

- [Общие правила](rules/workflow.md).
- [Стандарты разработки 1С](rules/1c-development.md).
- [Пакетные операции](skills/1c-batch/SKILL.md).
- [Синхронизация и сеансы](skills/1c-project-sync/SKILL.md).
- [Jira](skills/jira-workflow/SKILL.md).
- [Диагностика тестовых баз](skills/1c-test-db/SKILL.md).

Каждый разработчик клонирует 1c-common рядом со своими проектами. Имя папки 1c-common сохраняется: на него ссылаются проектные инструкции и скрипты. Общую реализацию изменяют здесь; в проектах .agents/skills содержат только точки входа.

Настройки баз находятся в личных рабочих копиях проектов. Для Jira предпочтительно встроенное подключение MCP; резервная настройка .jira-devbase.ps1 находится только в личной копии 1c-common и не публикуется. Адрес сервера и собственный токен разработчик получает у администратора команды. Реальные настройки агент применяет только через скрипты, не читает напрямую и не выводит.

После изменения name или description навыка обновите точки входа в своих проектах через tools/connect-project.ps1. При изменении остальных инструкций и скриптов повторное подключение не требуется.

1c-common и каждый проект имеют отдельные Git-репозитории. Локальные архивы, диагностические результаты и файлы подключения в состав библиотеки для публикации не входят.
