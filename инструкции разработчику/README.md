# Как использовать общую библиотеку

## 1. Получить папку

Нужны Git, Windows PowerShell и установленная платформа 1С подходящей версии. Клонируйте репозиторий команды в каталог с именем 1c-common. Каждый разработчик работает со своей копией и своими настройками подключения.

```powershell
git clone <URL-репозитория-команды> 1c-common
```

Ожидаемая структура:

```text
Работа/
├── 1c-common/             # Общая библиотека
└── Проекты/               # Пример одного проекта
    ├── AGENTS.md
    ├── .gitignore
    ├── .1c-devbase.ps1
    ├── .agents/skills/    # Генерируется подключением
    ├── doc/
    │   ├── AGENTS.md
    │   ├── MEMORY_BANK.md
    │   └── PROMT.md
    └── src/              # Выгрузка конфигурации
```

«Проекты» — нейтральное имя примера. Каталог каждого реального проекта может называться иначе, но должен находиться рядом с 1c-common, а не внутри него. Несколько проектов размещаются на одном уровне. Каждый проект — отдельный Git-репозиторий. Не переименовывайте 1c-common: существующие ссылки используют это имя.

## 2. Подключить проект

Сначала создайте каталог проекта и doc. Для нового проекта скопируйте файлы из [шаблонов](шаблоны). Уберите суффикс .template и разместите их по таблице. Для существующего проекта объедините инструкции с текущими; не заменяйте их и журнал задачи вслепую.

| Шаблон | Путь в проекте | Назначение |
|---|---|---|
| AGENTS.md.template | AGENTS.md | Подключение общих правил |
| doc-AGENTS.md.template | doc/AGENTS.md | Особенности конкретного проекта |
| MEMORY_BANK.md.template | doc/MEMORY_BANK.md | Состояние текущей задачи |
| PROMT.md.template | doc/PROMT.md | План текущей задачи |
| gitignore.template | .gitignore | Исключение личных настроек и временных файлов |

Из корня проекта выполните:

```powershell
& '../1c-common/tools/connect-project.ps1' -ProjectRoot (Get-Item -LiteralPath '.').FullName
```

Скрипт создаёт .agents/skills/<навык>/SKILL.md с относительными ссылками. Он не создаёт остальные проектные файлы, не подключается к базе и не копирует реализацию навыков. Если в .agents/skills уже есть собственная реализация, сначала согласуйте её перенос; скрипт не должен её затирать.

Содержимое rules, skills, scripts и tools поддерживается в 1c-common. В проекты не копируют общую реализацию. После переезда сохраняйте взаимное расположение папок.

## 3. Настроить личные подключения

Для 1С скопируйте [пустой шаблон](../skills/1c-batch/assets/.1c-devbase.ps1.example) в корень своего проекта под именем .1c-devbase.ps1. Файл сохраняйте в UTF-8 с BOM. Заполните его самостоятельно, не передавайте пароли в чат.

- ONEC_PATH — полный путь к исполняемому файлу установленной платформы.
- ONEC_SERVER и ONEC_BASE — сервер кластера 1С и имя информационной базы в кластере. Это не параметры СУБД.
- Для файловой базы вместо серверной пары задайте ONEC_FILEBASE_PATH.
- ONEC_USER и ONEC_PASSWORD — ваша учётная запись базы.
- ONEC_REPOSITORY_PATH, ONEC_REPOSITORY_USER и ONEC_REPOSITORY_PASSWORD — ваше подключение к хранилищу, если оно используется.

BAT-вариант необязателен: [шаблон](../skills/1c-batch/assets/.1c-devbase.bat.example). PowerShell предпочтителен; оба варианта настроек одновременно не требуются.

Для прямой диагностики SQL по отдельному разрешению: [шаблон .sql-devbase.psd1](../skills/1c-test-db/assets/sql-devbase.example.psd1) копируется в корень проекта. В нём указываются именно параметры СУБД. Этот файл не нужен для обычной выгрузки конфигурации.

Для Jira предпочтительно личное встроенное подключение MCP. Для резервного подключения скопируйте [шаблон Jira](../skills/jira-workflow/assets/.jira-devbase.ps1.example) в .jira-devbase.ps1 в корне СВОЕЙ копии 1c-common. Укажите согласованный адрес JIRA_MCP_URL и собственный JIRA_MCP_TOKEN. Не используйте чужой токен и не публикуйте настроенный файл. Подробности — [подключение Jira](../skills/jira-workflow/references/connection.md).

Настройки агент применяет только через штатные скрипты, не читает напрямую и не выводит. Наличие настроек не означает разрешение на подключение к базе: конкретную базу и действия согласовывают с пользователем.

## 4. Работать с проектом

Открывайте в рабочем инструменте корень нужного проекта. Перед задачей агент читает AGENTS.md, общие правила, doc/AGENTS.md и doc/MEMORY_BANK.md. Код конфигурации хранится в src. Журнал и план относятся только к текущему проекту; в общую библиотеку их не переносят.

Основные команды:

| Команда | Результат |
|---|---|
| Обнови проект | Выгрузить только изменённые объекты текущей конфигурации в src и открыть конфигуратор |
| Обнови конфигурацию | Загрузить согласованные изменения src в тестовую конфигурацию; учитывать обновление конфигурации БД |
| Запусти сеанс | Открыть конфигуратор и клиент 1С согласно навыку |
| Закрыть сеансы | Штатно закрыть подтверждённые сеансы целевой базы |
| Прочитай <ключ задачи> | Прочитать задачу Jira и подготовить план |
| Выполни промт | Выполнить актуальный doc/PROMT.md в пределах поручения |

Для обновления имеющейся файловой выгрузки используется `dump-config.ps1 src update`. Для первого создания src без ConfigDumpInfo.xml нужна отдельно запрошенная полная выгрузка. Получение из хранилища не подменяет выгрузку из текущей конфигурации и не выполняется этой командой автоматически. Не обновляйте файлы из старой копии конфигурации поверх локальных правок без сохранения работы.

## 5. Получать обновления библиотеки

Перед git pull проверьте git status в 1c-common и сохраните свои изменения. Обновление библиотеки не обновляет базы и исходники проектов. После изменения name или description навыков повторите connect-project.ps1 для своих проектов. При изменении только текста правил и скриптов повторная генерация не нужна.

Изменения общих правил обсуждайте с командой и вносите в репозиторий 1c-common. Проектные особенности оставляйте в doc/AGENTS.md своего проекта.
