# Как использовать общую библиотеку

## 1. Получить папку

Нужны Git, Windows PowerShell и установленная платформа 1С подходящей версии. Клонируйте репозиторий команды в каталог с именем 1c-common. Каждый разработчик работает со своей копией и своими настройками подключения.

```powershell
git clone <URL-репозитория-команды> 1c-common
```

Ожидаемая структура:

```text
Работа/
├── 1c-common/             # Общая библиотека
└── Проекты/               # Пример одного проекта
    ├── AGENTS.md
    ├── .gitignore
    ├── .1c-devbase.ps1
    ├── .agents/skills/    # Генерируется подключением
    ├── Vanessa/
    │   ├── project.json  # Назначенный клиент и статус проверки
    │   └── Scenarios/    # Прикладные .feature-файлы
    ├── extensions/
    │   ├── YAXUNIT/       # Движок YAxUnit
    │   └── Tests/         # Собственные тесты проекта
    ├── tests/yaxunit/
    │   ├── README.md
    │   ├── test-config.example.json
    │   └── results/       # Локальные отчёты
    ├── doc/
    │   ├── AGENTS.md
    │   ├── MEMORY_BANK.md
    │   └── PROMT.md
    └── src/              # Выгрузка конфигурации
```

«Проекты» — нейтральное имя примера. Каталог каждого реального проекта может называться иначе, но должен находиться рядом с 1c-common, а не внутри него. Несколько проектов размещаются на одном уровне. Каждый проект — отдельный Git-репозиторий. Не переименовывайте 1c-common: существующие ссылки используют это имя.

## 2. Подключить проект

Сначала создайте каталог проекта и doc. Для нового проекта скопируйте файлы из [шаблонов](шаблоны). Уберите суффикс .template и разместите их по таблице. Для существующего проекта объедините инструкции с текущими; не заменяйте их и журнал задачи вслепую.

| Шаблон | Путь в проекте | Назначение |
|---|---|---|
| AGENTS.md.template | AGENTS.md | Подключение общих правил |
| doc-AGENTS.md.template | doc/AGENTS.md | Особенности конкретного проекта |
| MEMORY_BANK.md.template | doc/MEMORY_BANK.md | Состояние текущей задачи |
| PROMT.md.template | doc/PROMT.md | План текущей задачи |
| gitignore.template | .gitignore | Исключение личных настроек и временных файлов |

Из корня проекта выполните:

```powershell
& '../1c-common/tools/connect-project.ps1' -ProjectRoot (Get-Item -LiteralPath '.').FullName
```

Скрипт создаёт .agents/skills/<навык>/SKILL.md с относительными ссылками, Vanessa/Scenarios/.gitkeep и Vanessa/project.json. По умолчанию назначает клиенту имя папки проекта и статус pending. При первом подключении другое имя можно задать параметром -VanessaProfileName 'Имя профиля'. Повторное подключение сохраняет существующую привязку и сценарии.

Профиль в Vanessa нужно настроить для тестовой базы проекта и проверить отдельно по [общему порядку](../skills/vanessa-mcp/references/project-layout.md); создание файлов не запускает 1С и не создаёт клиента. Остальные проектные файлы подготовьте по таблице шаблонов выше. Реализацию навыков скрипт не копирует. Если в .agents/skills уже есть собственная реализация, сначала согласуйте её перенос; скрипт не должен её затирать.

Содержимое rules, skills, scripts и tools поддерживается в 1c-common. В проекты не копируют общую реализацию. После переезда сохраняйте взаимное расположение папок.

Для тестирования через Vanessa используйте [общий комплект и инструкции](../Vanessa/README.md): файлы для установки, развёртывание менеджера, настройка профиля проекта и работа со сценариями.

Для алгоритмических тестов подготовлено [руководство YAxUnit](YAxUnit.md): установка движка, подключение тестового расширения проекта и разбор результатов. connect-project.ps1 теперь создаёт [файлы комплекта](../YAxUnit/README.md): движок в extensions/YAXUNIT и пустое расширение Tests в extensions/Tests, пример запуска и локальную настройку. Существующие каталоги сохраняются. Установка в базу и проверка совместимости выполняются отдельно.

## 3. Настроить личные подключения

Для 1С скопируйте [пустой шаблон](../skills/1c-batch/assets/.1c-devbase.ps1.example) в корень своего проекта под именем .1c-devbase.ps1. Файл сохраняйте в UTF-8 с BOM. Заполните его самостоятельно, не передавайте пароли в чат.

- ONEC_PATH — полный путь к исполняемому файлу установленной платформы.
- ONEC_SERVER и ONEC_BASE — сервер кластера 1С и имя информационной базы в кластере. Это не параметры СУБД.
- Для файловой базы вместо серверной пары задайте ONEC_FILEBASE_PATH.
- ONEC_USER и ONEC_PASSWORD — ваша учётная запись базы.
- ONEC_REPOSITORY_PATH, ONEC_REPOSITORY_USER и ONEC_REPOSITORY_PASSWORD — ваше подключение к хранилищу, если оно используется.

BAT-вариант необязателен: [шаблон](../skills/1c-batch/assets/.1c-devbase.bat.example). PowerShell предпочтителен; оба варианта настроек одновременно не требуются.

Для прямой диагностики SQL по отдельному разрешению: [шаблон .sql-devbase.psd1](../skills/1c-test-db/assets/sql-devbase.example.psd1) копируется в корень проекта. В нём указываются именно параметры СУБД. Этот файл не нужен для обычной выгрузки конфигурации.

Для Jira предпочтительно личное встроенное подключение MCP. Для резервного подключения скопируйте [шаблон Jira](../skills/jira-workflow/assets/.jira-devbase.ps1.example) в .jira-devbase.ps1 в корне СВОЕЙ копии 1c-common. Укажите согласованный адрес JIRA_MCP_URL и собственный JIRA_MCP_TOKEN. Не используйте чужой токен и не публикуйте настроенный файл. Подробности — [подключение Jira](../skills/jira-workflow/references/connection.md).

Настройки агент применяет только через штатные скрипты, не читает напрямую и не выводит. Подключение к конфигуратору 1С и хранилищу разрешено пользователем по умолчанию во всех проектах; повторное подтверждение не требуется. Явное разрешение на конкретную СУБД/базу и действия требуется для прямого доступа к СУБД. Объём операций определяется поручением и общими правилами.

## 4. Работать с проектом

Открывайте в рабочем инструменте корень нужного проекта. Перед задачей агент читает AGENTS.md, общие правила, doc/AGENTS.md и doc/MEMORY_BANK.md. Код конфигурации хранится в src. Журнал и план относятся только к текущему проекту; в общую библиотеку их не переносят.

Основные команды:

| Команда | Результат |
|---|---|
| Обнови проект | Выгрузить изменения текущей конфигурации базы в src, включая сохранённые ручные правки, и восстановить сеансы; без получения из хранилища, обновления БД и автоматических коммитов |
| Обнови проект из хранилища | Сохранить локальные файлы коммитом, выгрузить и закоммитить ручные правки из базы, получить изменения из хранилища, обновить БД, повторно выгрузить src, восстановить сеансы и создать коммит «Из хранилища <Дата>» |
| Обнови конфигурацию | Загрузить согласованные изменения src в тестовую конфигурацию; учитывать обновление конфигурации БД |
| Проверь доработку | Проверить текущую доработку через [YAxUnit](../skills/yaxunit/SKILL.md): подготовить нужные тесты, адресно загрузить, запустить и сообщить результат в пределах согласованных действий |
| Проверь эту доработку через Vanessa | Проверить текущую доработку через интерфейс 1С по [vanessa-mcp](../skills/vanessa-mcp/SKILL.md): подготовить нужный сценарий, проверить клиент проекта, выполнить согласованные действия и разобрать результат |
| Запусти сеанс | Открыть конфигуратор и клиент 1С согласно навыку |
| Закрыть сеансы | Штатно закрыть подтверждённые сеансы целевой базы |
| Прочитай <ключ задачи> | При смене задачи создать коммит предыдущей работы с её номером и описанием ровно из пяти слов, затем обработать прежние материалы, прочитать новую задачу Jira и подготовить план |
| Выполни промт | Выполнить актуальный doc/PROMT.md в пределах поручения |

Команда «Обнови проект» сохраняет прежний режим: `dump-config.ps1 src update` из текущей конфигурации базы и восстановление сеансов. Она не получает изменения из хранилища, не обновляет конфигурацию БД и не создаёт Git-коммиты автоматически.

Полный цикл [«Обнови проект из хранилища»](../skills/1c-project-sync/SKILL.md#обнови-проект-из-хранилища): при наличии локальных изменений создаётся коммит `Перед обновлением из хранилища <ДД.ММ.ГГГГ>`, затем текущая конфигурация базы выгружается в src и её отличия сохраняются коммитом `Ручные правки из базы <ДД.ММ.ГГГГ>`. Только после этого получаются изменения из хранилища и обновляется конфигурация БД. После завершения реструктуризации выполняются повторная выгрузка и коммит результата `Из хранилища <ДД.ММ.ГГГГ>`. Даты берутся в часовом поясе пользователя. При ошибке этапа зависимые действия не выполняются; пустые коммиты не создаются. Для первого создания src без ConfigDumpInfo.xml в обеих командах нужна отдельно согласованная полная выгрузка.

## 5. Получать обновления библиотеки

Перед git pull проверьте git status в 1c-common и сохраните свои изменения. Обновление библиотеки не обновляет базы и исходники проектов. После изменения name или description навыков повторите connect-project.ps1 для своих проектов. При изменении только текста правил и скриптов повторная генерация не нужна.

Изменения общих правил обсуждайте с командой и вносите в репозиторий 1c-common. Проектные особенности оставляйте в doc/AGENTS.md своего проекта.
## YAxUnit для проверки доработок агентом

[Общий навык yaxunit](../skills/yaxunit/SKILL.md) подключается вместе с остальными навыками через tools/connect-project.ps1. Он задаёт подготовку тестов, адресную загрузку собственного расширения, запуск выбранным клиентом и проверку свежего результата. [Руководство YAxUnit](YAxUnit.md) описывает установку стенда.

После подключения нового проекта определите готовность движка и расширения, клиент и конфигурацию запуска в doc/AGENTS.md. Не копируйте параметры кассы или её клиент во все проекты. Само подключение навыка не меняет базы. Общая команда — «Проверь доработку». Полный вариант «Проверь эту доработку через YAxUnit» означает то же действие. Команда относится к текущему проекту и доработке; требования к готовности стенда и разрешениям описаны в навыке.
