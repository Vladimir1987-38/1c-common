# Подготовка публикации в GitHub

## Что публиковать

Публикуйте README.md, AGENTS.md, .gitignore и каталоги rules, skills, scripts, tools, «инструкции разработчику». Пустые *.example и *.template входят в комплект. Исходники конкретных проектов находятся в отдельных репозиториях.

Не публикуйте реальные .1c-devbase.ps1, .1c-devbase.bat, .jira-devbase.ps1, .sql-devbase.psd1, .env, токены, журналы, .migration-backup и .validation. Они исключены в .gitignore. Игнорирование не удаляет файл, уже находящийся в Git или его истории.

## Первая публикация обезличенного комплекта

Существующая история рабочей копии может содержать прежние названия проектов, личные логины и внутренние адреса. Чтобы опубликовать именно обезличенное текущее содержимое, создайте отдельный каталог публикации. Скопируйте в него только перечисленные выше файлы и каталоги; не копируйте .git и личные файлы из корня. Это не меняет работающую локальную библиотеку и сохраняет её историю у владельца.

В отдельном каталоге публикации:

```powershell
git init
git add -- README.md AGENTS.md .gitignore rules skills scripts tools 'инструкции разработчику'
git diff --cached --stat
git diff --cached
```

Просмотрите подготовленные изменения, убедитесь в отсутствии личных настроек и секретов. Затем сделайте первый коммит, добавьте адрес выбранного репозитория GitHub и отправьте его обычным порядком команды. Видимость репозитория и доступ участников задаёт владелец. Не отправляйте существующую историю рабочей библиотеки без отдельной проверки всех её версий.

Разработчики клонируют опубликованный репозиторий под именем 1c-common и следуют README.md в этой папке. Существующая локальная библиотека владельца продолжает работать на прежнем месте; её настроечные файлы не заменяют примерами.

## Что остаётся локальным

Адрес Jira задаётся в личном JIRA_MCP_URL, токен — в JIRA_MCP_TOKEN. Настройки баз каждый разработчик заполняет для своего проекта. Изменять права сетевой папки для работы через GitHub не требуется. Создание репозитория, загрузка файлов и приглашение команды выполняются отдельно владельцем.
