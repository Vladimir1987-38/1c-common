# YAxUnit в проекте

Файлы подготовлены. Установка расширений в тестовой базе и совместимость ещё не проверены.

- [Движок YAXUNIT 25.12](../../extensions/YAXUNIT/Configuration.xml) — общая поставка; прикладные тесты сюда не добавляют.
- [Расширение Tests](../../extensions/Tests/Configuration.xml) — пустой каркас для тестов именно этого проекта. Тестов кассы и регистраций тестов в нём нет.
- [Пример запуска](test-config.example.json) — общий образец. initialize-project.ps1 создаёт рядом test-config.local.json с абсолютным workspacePath текущего проекта; этот файл исключён из Git.
- results — локальные результаты, исключённые из Git.

## Что делать дальше

1. Выбрать разрешённую тестовую базу этого проекта, платформу и клиент. Настройки кассы сюда не переносятся. Для мобильной конфигурации отдельно определить возможность тестирования в настольной тестовой базе; запуск на мобильной платформе не подтверждён.
2. Установить движок YAXUNIT и создать/загрузить собственное Tests штатными инструментами конфигуратора. Это XML/BSL-исходники, не готовые CFE. Порядок установки и сборки — в [общем руководстве](../../../1c-common/инструкции%20разработчику/YAxUnit.md).
3. Проверить применимость расширений, язык Русский и права. Tests не содержит заимствований прикладных объектов. ConfigDumpInfo.xml не копируется из кассы: после загрузки/выгрузки его формирует платформа.
4. Добавить тестовый общий модуль и регистрацию ИсполняемыеСценарии для проверяемой доработки. Указать нужные модули в filter.modules локальной настройки; пустой список выбирает весь Tests, поэтому перед запуском проверить состав.
5. Запустить согласованный тест с параметром /C"RunUnitTests=<полный путь к tests/yaxunit/test-config.local.json>" в нужном клиенте. Пустое Tests даёт ноль тестов — это не успешная проверка.
6. Смотреть results/report.xml и results/result.txt, проверять свежесть и фактический состав. После подтверждённого прогона записать клиент, базу без секретов и состояние стенда в doc/AGENTS.md.

При переносе проекта на другое рабочее место создайте test-config.local.json из примера и задайте workspacePath. Повторное подключение сохраняет настройки tests/yaxunit и исходники extensions/Tests.
