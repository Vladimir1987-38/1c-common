# Подключение проекта тестирования

[Начало](../README.md) · [Развёртывание менеджера](deployment.md) · [Работа со сценариями](usage.md).

## 1. Создать привязку проекта

Общая библиотека 1c-common и папка проекта располагаются рядом. Из корня проекта выполните:

~~~powershell
& '../1c-common/tools/connect-project.ps1' -ProjectRoot (Get-Item -LiteralPath '.').FullName
~~~

Команда создаёт точки входа общих навыков и каркас:

~~~text
<проект>/
  Vanessa/
    project.json
    Scenarios/
  doc/
    AGENTS.md
~~~

При первом подключении другое имя клиента задаётся параметром -VanessaProfileName 'Имя профиля'. Для уже подключённого к общим навыкам проекта можно добавить только каркас:

~~~powershell
& '../1c-common/skills/vanessa-mcp/scripts/initialize-project.ps1' -ProjectRoot (Get-Item -LiteralPath '.').FullName
~~~

Во втором скрипте параметр имени называется -ProfileName. Повторный вызов сохраняет существующие привязку и сценарии. Скрипты не создают профиль в 1С и не запускают клиент.

Формат, значения статусов и правила изменения определены в одном месте: [project-layout.md](../../skills/vanessa-mcp/references/project-layout.md). Имя нового профиля по умолчанию совпадает с именем папки проекта; pending означает, что его ещё нужно настроить и проверить. Адрес базы и пароль в project.json не хранятся.

## 2. Подготовить тестовую базу

Используйте согласованную тестовую копию конкретного проекта. Установите в неё [VAExtension.1.41.cfe](../distributions/1.2.043.45/VAExtension.1.41.cfe) через управление расширениями, проверьте применимость и перезапустите тестовый сеанс.

При несовместимости разберите её до продолжения: см. [развёртывание](deployment.md). Факт, что адаптированное расширение работает в другом проекте, не доказывает применимость этого файла.

Подготовьте тестового пользователя с нужными правами, исходные данные и необходимые тестовые режимы оборудования/обменов. Для разных проектов условия различаются; запишите их в проектной инструкции рядом со сценариями.

## 3. Настроить профиль Vanessa

В менеджере откройте «Клиенты тестирования» и создайте отдельную строку:

| Поле | Что указать |
|---|---|
| Имя | Точное testClient.profileName из Vanessa/project.json |
| База | Файловый каталог или строка соединения согласованной тестовой базы |
| Тип клиента | Тип, в котором требуется проверять приложение: например, толстый или тонкий |
| Платформа | Установленная совместимая версия и путь запуска |
| Компьютер и порт тестирования | Параметры подключения клиента 1С; это не порт MCP |
| Дополнительные параметры | Учётная запись пользователя базы и требуемые параметры запуска, локально |

Имя профиля — метка, а не адрес базы. Два профиля с похожими именами могут вести в разные базы. Проверьте строку подключения; исходная строка Vanessa может относиться к самой базе менеджера.

Выделите нужную строку и подключите клиент штатной командой Vanessa (в этой версии Ctrl+T). При запуске через Vanessa клиент получает режим тестирования; обычный сеанс приложения не является автоматически подключённым тестовым клиентом. Учётная запись информационной базы и авторизация сотрудника внутри прикладной формы — отдельные этапы.

## 4. Подтвердить принадлежность клиента

В пределах разрешения на этот проект:

1. Получите состояние Vanessa.
2. Прочитайте окна уже подключённого клиента через get_window_list_testclient.
3. Сверьте фактический профиль, базу и открытые формы с проектом. Одного совпадения заголовка окна недостаточно, если он одинаков в нескольких базах.
4. После успешной проверки запишите в Vanessa/project.json status = verified и дату проверки YYYY-MM-DD в verifiedAt.
5. При ошибке оставьте pending. При смене базы/имени профиля сбросьте статус и дату, затем повторите проверку.

Проверка окон не выполняет сценарий и не подтверждает прикладной результат. Подробный порядок действий агента — [общий навык](../../skills/vanessa-mcp/SKILL.md).

## 5. Подключить сценарии

Сохраняйте прикладные feature-файлы в Vanessa/Scenarios данного проекта. В шаге подключения клиента указывайте точное имя из project.json. Перед выполнением сверяйте его с реально выбранным профилем.

Пути к тестовым кодам и другим секретам направляйте в локальные файлы, исключённые из Git. Дистрибутив, базы, личные профили и временные отчёты в Scenarios не размещайте. Список условий запуска и ожидаемый результат каждого теста должны быть понятны следующему разработчику.

Существующий сценарий кассы не становится общим сценарием при подключении другого проекта: его шаги, формы и условия относятся к конкретной конфигурации.
