# Использование и настройка Vanessa

[Начало](../README.md) · [Развёртывание](deployment.md) · [Подключение проекта](project-setup.md).

## Начало работы

1. Откройте нужный проект и прочитайте tests/vanessa/project.json.
2. Запустите подготовленный менеджер с /TESTMANAGER и внешней обработкой Vanessa; дождитесь запуска MCP.
3. В «Клиенты тестирования» выберите профиль именно этого проекта, подключите его и подтвердите целевую базу.
4. Откройте требуемый feature-файл из tests/vanessa/Scenarios. При запуске через агента назовите файл или сценарий и разрешённый результат.
5. Перед действиями приведите приложение к описанному начальному состоянию: нужный экран, тестовые данные, отсутствие незавершённой операции.

Один менеджер может хранить несколько профилей, но текущий подключённый клиент нужно проверять при смене проекта. Параллельные прогоны в одном управляемом UI-сеансе не используйте.

## Подготовка и выполнение сценария

При подготовке нового теста используйте библиотеку шагов установленной Vanessa и фактические имена элементов. Запись действий помогает получить шаги; ожидаемый результат добавляется отдельно.

Проверяйте видимость и доступность нужной страницы/элемента. Наличие элемента в общей форме не всегда означает, что пользователь сейчас видит его. Для окон с пустым или переменным заголовком при наличии соответствующего шага используйте подтверждённое внутреннее имя формы. Динамические кнопки выбирайте по смыслу и проверяйте неоднозначность.

Сначала загрузите файл и выполните синтаксическую проверку, затем запустите согласованный сценарий. Не расширяйте запуск одного сценария до всего набора. Вручную используйте команды загрузки и выполнения Vanessa; через MCP — фактически доступные load_features, check_syntax и run_scenario с параметрами из текущей схемы сервера.

После выполнения получите get_test_results. Зафиксируйте:

- имя сценария и целевой клиент;
- статус, количество выполненных и ошибочных шагов;
- ожидаемый и фактический результат;
- при ошибке — первый сбойный шаг, текст и активную форму.

Success не означает проверку всего приложения. Например, UI-проверка оформления документа не доказывает доставку его во внешнюю систему без отдельного ожидания такого результата.

## Длительность и повторный запуск

У таймаута MCP-вызова и ожидания элемента в сценарии разные назначения. Ожидание элемента задаёт предел ожидания, а не обязательную паузу. Продолжительность шага может включать медленный поиск и вызовы механизма тестирования 1С.

Лимит MCP-вызова выбирайте с учётом длительности полного прогона и настроек обеих сторон. Пример в инструкции развёртывания — 900 секунд. Для короткой проверки связи такой длительный предел обычно не нужен.

Если вызов завершился таймаутом, сценарий может продолжать выполнение. Сначала получите состояние и результат прежнего запуска. Не отправляйте run_scenario повторно только из-за таймаута: это может повторить продажу, оплату или другую операцию.

После ошибки определите, успел ли сценарий изменить данные. Продолжение со строки допустимо только при известном состоянии и сохранённом контексте. Перед запуском с начала незавершённый документ обрабатывают штатным способом в рамках разрешённой задачи; нельзя предполагать, что перезапуск клиента его отменил.

Для ускорения сравнивайте длительности шагов. Сужайте область поиска элементов и количество повторных обращений к форме по результатам измерений. Удаление проверок результата ради сокращения времени делает тест менее полезным.

## Где хранить настройки

| Что | Где |
|---|---|
| Дистрибутив и расширения команды | 1c-common/Vanessa/distributions/<версия> |
| Рабочая копия инструментов | Локальный каталог разработчика |
| База менеджера, её настройки и профили | Локальный стенд вне Git |
| Имя клиента и статус проверки | <проект>/tests/vanessa/project.json |
| Прикладные сценарии | <проект>/tests/vanessa/Scenarios |
| Секреты и личные тестовые данные | Локальные файлы, исключённые из Git |
| Общие правила агента | 1c-common/skills/vanessa-mcp |
| Условия конкретной базы | doc/AGENTS.md и описание сценариев проекта |
| Существенные результаты текущей задачи | doc/MEMORY_BANK.md |

Параметры запуска и файлов настроек текущего выпуска описаны в [документации поставки](../distributions/1.2.043.45/vanessa-automation/docs/JsonParams/JsonParamsRU.md). Выгруженные настройки могут содержать строки подключения и учётные данные; не публикуйте их целиком.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| MCP не отвечает | Открыт ли менеджер, запущен ли сервер, совпадают ли адрес/порт и среда обращения к localhost |
| Видно только infobase_info | Открыта ли Vanessa, зарегистрированы ли её инструменты, обновлён ли каталог MCP-клиента |
| Клиент не подключён | Правильный профиль, адрес базы, тип/версия платформы, окно входа и порт тестирования |
| Ошибка применимости расширения | Какое расширение и в какой базе устанавливается, режим совместимости и точный текст ошибки |
| Не загружается внешняя компонента | VanessaExt или транспорт MCP, ОС, разрядность, ограничения именно этой компоненты |
| Не найдено «Да» или другая кнопка | Реально открытая форма и предыдущие шаги; не нажимать произвольную кнопку для продолжения |
| Неизвестен шаг сценария | Библиотеки данной поставки, формулировка и результат синтаксической проверки |
| HTTP-вызов завершился таймаутом | Состояние и результат исходного запуска; не дублировать операцию |
| Проверка занимает долгое время | Протокол длительности шагов, поиск по всей форме, готовность приложения |

Для неполного каталога инструментов и резервной диагностики: [diagnostics.md](../../skills/vanessa-mcp/references/diagnostics.md). Явные ограничения доступа не обходят прямым вызовом HTTP.

## Обновление и завершение работы

Новую поставку размещайте отдельным каталогом. На выделенном стенде проверьте загрузку библиотек, компонент, применимость расширений, связь MCP, нужного клиента и выбранный тест. После этого переключайте рабочий ярлык и пути библиотек. Откат включает прежний дистрибутив и, если менялись расширения/базы, заранее подготовленное восстановление этих частей.

Перед закрытием менеджера дождитесь результата активного теста. Сохраните сценарий и краткий итог. Закрытие менеджера прекращает MCP; не используйте его как способ узнать результат зависшего HTTP-вызова.

Примеры поручений агенту:

- «Проверь Vanessa и прочитай окна клиента из project.json. Сценарии не запускай».
- «Подготовь сценарий в tests/vanessa/Scenarios для указанного поведения; пока без запуска».
- «Выполни сценарий <имя файла> в тестовой базе проекта и сообщи результат».

## Воспроизведение проверки текущей задачи

После тестирования сохранить tests/REPRODUCE.md в проекте: профиль и база без секретов, ручная подготовка клиента, загрузка конкретного feature-файла, запуск выбранного сценария, ожидаемые шаги и результат, разбор ошибки и очистка данных. При смене задачи прежняя инструкция уходит в архив либо удаляется по [общему правилу](../../rules/workflow.md#инструкция-воспроизведения-тестирования); в рабочем файле остаётся только новая задача.
