# Развёртывание Vanessa и MCP

[Комплект и порядок работы](../README.md). Инструкция для нового рабочего места; существующий менеджер автоматически не переносится. Проверена по документации поставки Vanessa 1.2.043.45. В этом этапе подготовлены файлы и инструкция; развёртывание новой базы по ней не выполнялось.

## 1. Подготовить рабочее место

Нужны Windows, установленная и лицензированная платформа 1С, права создать отдельную базу менеджера и согласованная тестовая база проекта. Для CLI-примеров используется Windows PowerShell. Версию платформы, разрядность и тип тестового клиента выбирайте под тестируемую конфигурацию.

Зафиксируйте локально:

| Параметр | Пример; замените своим значением |
|---|---|
| Каталог инструментов | C:\\1C-Tests\\Tools\\1.2.043.45 |
| Файловая база менеджера | C:\\1C-Tests\\Manager |
| Платформа менеджера | Полный путь к установленному 1cv8.exe |
| Тестовая база | Отдельная разрешённая копия целевого проекта |
| MCP | http://127.0.0.1:9876/mcp; свободный порт на данном компьютере |
| Имя клиента | Из Vanessa/project.json целевого проекта |

Порт MCP и порт клиента тестирования 1С — разные настройки. Адрес 127.0.0.1 подходит, если MCP-клиент и менеджер доступны в одной сетевой среде. При запуске агента в контейнере, WSL или на другом компьютере адрес нужно определить отдельно.

## 2. Получить файлы

После клонирования Git скачайте девять частей поставки с [Wiki](https://wiki.spb.teremok.ru/pages/viewpage.action?pageId=163548689), соберите vanessa-1.2.043.45.zip и проверьте SHA-256 по инструкции на странице. [Состав и контрольная сумма комплекта](../README.md#файлы-для-развёртывания). Поставка не входит в Git. Распакуйте архив в Vanessa/distributions/1.2.043.45 либо сразу в выбранный локальный каталог инструментов, сохранив структуру и лицензии. Если локальная поставка уже есть, её можно скопировать целиком. Ожидаемое размещение:

~~~text
C:\1C-Tests\Tools\1.2.043.45\
  client_mcp.cfe
  VAExtension.1.41.cfe
  vanessa-automation\
    vanessa-automation.epf
    features\
    lib\
    docs\
    ... остальные каталоги поставки
~~~

Один EPF из обычного дистрибутива не заменяет полную папку. Не используйте examples или lib/CF как готовую базу вашей прикладной системы: это материалы поставки Vanessa.

Исходный комплект и лицензии описаны в [README](../README.md). Дистрибутив платформы 1С и базы в этот комплект не включены.

## 3. Создать базу менеджера

1. В стартовом окне 1С нажмите «Добавить» → создание новой информационной базы → создание без конфигурации. Выберите отдельный файловый каталог менеджера.
2. Откройте её в конфигураторе. Проверьте управляемый режим запуска и совместимость с выбранной платформой. Сохраните и обновите конфигурацию базы менеджера.
3. Откройте «Конфигурация → Расширения конфигурации» и загрузите client_mcp.cfe. Проверьте применимость и активность расширения. Обеспечьте пользователю менеджера права на его команды.
4. Перезапустите сеанс после установки расширения. Если возникает ошибка внешней компоненты, проверьте её текст, разрядность и настройки безопасности именно этого расширения.
5. В дополнительных параметрах запуска базы менеджера укажите /TESTMANAGER. Запустите менеджер и откройте vanessa-automation/vanessa-automation.epf.
6. В Vanessa: «Сервис → Основные» → включите использование внешней компоненты VanessaExt и убедитесь, что загрузка прошла без ошибки. Каталог инструментов и библиотеки шагов должны относиться к этой копии поставки.
7. Откройте форму «Управление MCP». Укажите выбранный порт и нажмите «Запустить». После открытия Vanessa в списке инструментов должны появиться её команды.

client_mcp использует транспортную компоненту AddIn.WebTransport.mcp, а Vanessa — VanessaExt. Это разные компоненты. VAExtension.cfe устанавливается в тестируемую базу, а не заменяет ни одну из них.

По исходникам соответствующих выпусков у client_mcp v0.6.6 совместимость 8.3.20, у VAExtension 1.41 — 8.3.14. Эти значения не являются полной матрицей совместимости. При отказе применимости разберите сообщение платформы. Не понижайте совместимость расширения или не меняйте прикладную конфигурацию автоматически; адаптированную сборку проверяют и учитывают отдельно.

Основание: [MCP из поставки](../distributions/1.2.043.45/vanessa-automation/docs/AI/index.md), [client_mcp v0.6.6](https://github.com/1c-neurofish/onec-client-mcp-devkit/tree/v0.6.6).

## 4. Настроить удобный запуск

После успешного ручного открытия создайте ярлык. Пример строки запуска для уже созданного менеджера:

~~~text
"C:\Program Files\1cv8\<версия>\bin\1cv8.exe" ENTERPRISE /F "C:\1C-Tests\Manager" /TESTMANAGER /Execute "C:\1C-Tests\Tools\1.2.043.45\vanessa-automation\vanessa-automation.epf" /C "runMcp;mcpPort=9876"
~~~

Замените платформу, пути и порт. Если /C уже используется, объедините его параметры осмысленно; не добавляйте второй независимый /C. Этот запуск открывает менеджер и MCP; сценарии им не запускаются. Параметры пользователя базы задавайте локально, пароли в общий ярлык и репозиторий не включайте.

Открытый сеанс менеджера нужен на всё время работы MCP. После его закрытия сервер недоступен. Не запускайте два менеджера на одном порту.

## 5. Подключить Codex

В локальном Codex CLI можно добавить сервер командой:

~~~powershell
codex mcp add vanessa --url http://127.0.0.1:9876/mcp
~~~

Если запись vanessa уже существует, отредактируйте её адрес, сохранив остальные настройки. Для клиента, использующего config.toml, пример секции:

~~~toml
[mcp_servers.vanessa]
url = "http://127.0.0.1:9876/mcp"
enabled = true
startup_timeout_sec = 30
tool_timeout_sec = 900
~~~

900 секунд — пример лимита для длительного UI-сценария, а не обязательная настройка всех проектов. Настройте согласованный предел также на стороне MCP-сервера. Увеличение таймаута не ускоряет тест. Параметры подтверждены [документацией Codex](https://developers.openai.com/codex/mcp/); командная форма сверена с локальным codex mcp add --help.

Если приложение управляет подключением через собственные настройки MCP, укажите там Streamable HTTP и тот же URL. Обновите подключение/список инструментов после запуска Vanessa. Не создавайте второй сервер только из-за неполного списка в текущем чате.

## 6. Проверить результат

1. Менеджер открывается с /TESTMANAGER, Vanessa и компоненты загружаются.
2. MCP-сервер работает на согласованном порту; клиент получает инструменты Vanessa.
3. Вызов get_vanessa_automation_state возвращает ответ. Отсутствие загруженного или выполненного сценария допустимо.
4. Подключите проект и подтвердите нужные окна по [следующей инструкции](project-setup.md).
5. Только после подготовки исходных данных выполните отдельно выбранный небольшой тест и получите его фактический результат.

Один ответ infobase_info подтверждает связь с 1С/MCP, но не готовность Vanessa и прикладного клиента. При неполном каталоге используйте [диагностику общего навыка](../../skills/vanessa-mcp/references/diagnostics.md).

Новый стенд считается настроенным после проверки именно на этом рабочем месте. История успешного сценария на другом стенде не заменяет такую проверку.
