# Подключение Confluence через MCP

## Существующее подключение

Сначала проверить доступные инструменты. Если confluence_search/get_page уже доступны через jira, отдельная запись confluence-mcp не обязательна. Проверять чтением запрошенной страницы; для проверки подключения без страницы допустим confluence_search с query="type=page", limit=1. Успех подтверждает только выполненное чтение, не все пространства и не права записи.

## Конфигурация Codex

При отдельном подключении добавить в пользовательский ~/.codex/config.toml следующий блок, не создавая второй блок с тем же именем. Имя сервера произвольно. URL должен быть обычной строкой, не Markdown-ссылкой; параметры записывать на отдельных строках, без обратных слешей перед подчёркиваниями.

```toml
[mcp_servers.confluence-mcp]
enabled = true
startup_timeout_sec = 20
tool_timeout_sec = 60
url = "http://jira-mcp.teremok-spb.local:9000/mcp"
bearer_token_env_var = "CONFLUENCE_PAT"
enabled_tools = ["confluence_get_page", "confluence_search"]
```

Это шаблон чтения. Если пользователь отдельно поручит редактирование, список можно расширить confluence_create_page/confluence_update_page; само наличие инструментов не разрешает запись.

bearer_token_env_var задаёт имя переменной окружения с Bearer-токеном для HTTP-сервера MCP. Название CONFLUENCE_PAT не доказывает, что сюда подходит персональный токен самого Confluence. Администратор указанного MCP должен подтвердить способ авторизации: отдельный токен MCP, передача пользовательского PAT или серверная учётная запись Confluence. Не подменять реквизиты одного уровня другим наугад.

В Windows пользователь задаёт подтверждённый токен локально через «Переменные среды» → «Переменные пользователя» → CONFLUENCE_PAT. Затем полностью перезапускает Codex, чтобы приложение получило новую переменную. Токен не присылать в чат и не вставлять в отслеживаемые файлы. После изменения конфигурации проверить наличие инструментов в новом сеансе и чтение конкретной доступной страницы.

## Диагностика

- MCP не инициализируется: проверить адрес, доступ из корпоративной сети, имя переменной и требования авторизации MCP.
- MCP отвечает, но инструмент сообщает Confluence API 401/403: проверить на стороне интеграции действительность реквизитов Confluence, активность учётной записи, права на пространство/страницу и соответствие токена целевому серверу. Ошибка не доказывает конкретную причину без серверной диагностики.
- Пустая выдача не равна отсутствию страницы: учесть права, фильтры пространств и поиск по другому названию. Проверить известную ссылку через get_page.
- Не переходить к прямому REST и не пересылать токен на другие адреса ради обхода отказа доступа.
