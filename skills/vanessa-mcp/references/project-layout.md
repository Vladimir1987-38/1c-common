# Каталоги Vanessa и клиент проекта

При подключении нового проекта или изменении привязки использовать эту инструкцию. При обычном запуске достаточно прочитать Vanessa/project.json текущего проекта и общий SKILL.md.

## Структура

```text
<проект>/
├── Vanessa/
│   ├── project.json
│   └── Scenarios/
│       └── .gitkeep
└── doc/AGENTS.md
```

- Vanessa/Scenarios — рабочий каталог прикладных .feature-файлов текущей задачи и их подпапок. Относительные пути сценариев разрешать от этого каталога. При выборе архива перенести завершённый набор в doc/archive/<номер предыдущей задачи>/Vanessa/Scenarios по [общему порядку](../../../rules/workflow.md#тесты-при-архивировании), а рабочий каталог сохранить для новой задачи.
- Vanessa/project.json — единственный источник привязки клиента данного проекта. Хранить в Git; имя профиля и статус не являются секретами.
- .gitkeep сохраняет пустой каталог в Git. Сценарии, инструкции и общие библиотеки шагов — разные материалы; прикладные сценарии не переносить в 1c-common.
- Дистрибутив Vanessa, расширения, отчёты и временные логи не входят в этот каркас. Секреты и персональные тестовые данные в отслеживаемые файлы не добавлять.
- Существующий сценарий в другом каталоге использовать по его явному пути. Переносить по отдельному поручению, проверяя ссылки и секреты; создание каркаса его не переносит.

## Формат project.json

```json
{
  "schemaVersion": 1,
  "projectName": "ExampleProject",
  "scenariosPath": "Scenarios",
  "testClient": {
    "profileName": "ExampleProject",
    "status": "pending",
    "verifiedAt": null
  }
}
```

| Поле | Значение |
|---|---|
| schemaVersion | Версия формата: 1. |
| projectName | Точное имя папки проекта. При переименовании проекта пересмотреть привязку. |
| scenariosPath | Scenarios, относительно папки Vanessa. |
| testClient.profileName | Точное имя профиля в таблице «Клиенты тестирования» Vanessa. Для нового проекта по умолчанию совпадает с именем его папки; это назначение имени, а не подтверждение существования профиля. |
| testClient.status | pending — профиль нужно настроить и проверить; verified — принадлежность клиента этому проекту и чтение его окон подтверждены. |
| testClient.verifiedAt | Дата последней успешной проверки YYYY-MM-DD; для pending — null. Историческая проверка не гарантирует текущее подключение. |

Адреса баз, строки соединения, пароли, токены и параметры входа сюда не записывать. Реальное подключение настраивается в профиле Vanessa для согласованной тестовой базы проекта. Не заменять эту базу базой менеджера или соседа. Разрешения пользователя не хранить в JSON как постоянный допуск.

Полный порядок подготовки менеджера и профиля: [общие инструкции разработчику](../../../Vanessa/README.md). Установочные файлы находятся в общей библиотеке, а не в каркасе прикладного проекта.

## Подключение нового проекта

Из корня проекта выполнить:

```powershell
& '../1c-common/tools/connect-project.ps1' -ProjectRoot (Get-Item -LiteralPath '.').FullName
```

Если нужен профиль с другим именем, при первом подключении передать `-VanessaProfileName 'Имя профиля'`. Скрипт создаёт проектные точки входа навыков и каркас Vanessa. Привязка создаётся со статусом pending; профили в 1С при этом не создаются и клиент не запускается.

Для добавления только каркаса в уже подключённый проект:

```powershell
& '../1c-common/skills/vanessa-mcp/scripts/initialize-project.ps1' -ProjectRoot (Get-Item -LiteralPath '.').FullName
```

У этого скрипта имя задаётся параметром `-ProfileName`. Повторный вызов сохраняет существующий project.json и сценарии. Несовпадение явно переданного имени с записанным считается ошибкой; автоматического переключения клиента нет.

После создания каркаса:

1. В doc/AGENTS.md сохранить ссылку на собственный Vanessa/project.json и общий навык, как в [шаблоне](<../../../инструкции разработчику/шаблоны/doc-AGENTS.md.template>).
2. По разрешению пользователя настроить профиль с назначенным именем для тестовой базы именно этого проекта. Наличие локального .1c-devbase.ps1 само по себе не подтверждает готовность профиля Vanessa.
3. В пределах разрешения подключить этот профиль, проверить окна и принадлежность базы. При успехе записать status=verified и фактическую дату проверки в verifiedAt. При неудаче оставить pending и сообщить причину.
4. Новые сценарии сохранять в Vanessa/Scenarios. Перед запуском сверять цель из JSON с фактически выбранным профилем и текстом самого сценария.

Для изменения привязки по поручению пользователя отредактировать profileName, установить pending и очистить verifiedAt. Затем выполнить новую проверку. Не считать историю успешного запуска другого клиента проверкой новой привязки.
