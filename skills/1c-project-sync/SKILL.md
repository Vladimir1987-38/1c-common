# Синхронизация проекта и сеансы 1С

Прочитать doc/AGENTS.md целевого проекта и [1c-batch](../1c-batch/SKILL.md). Параметры скриптов определены в 1c-batch. Выполнять их из корня целевого проекта через ../1c-common/skills/1c-batch/scripts/. Предпочитать PowerShell; BAT использовать при отсутствии доступной PowerShell-настройки или PowerShell.

## Целевая база

Работать только с тестовой базой из локального .1c-devbase.ps1 или .1c-devbase.bat. Единственный источник цели — текущая настройка; название проекта, Memory Bank, IBName и похожий заголовок окна не определяют подключение.

Настройку применяет штатный скрипт; не читать и не выводить её содержимое. При необходимости сопоставить процессы выполнить её в изолированной области процесса и сравнить параметры подключения без вывода учётных данных. Перед изменяющей операцией сообщить целевой сервер и базу либо путь файловой базы без логина и пароля. Версию платформы проверять по текущей настройке и серверу, не фиксировать общую версию для разных баз.

## Сеансы

1. Зафиксировать исходные сеансы целевой базы и состояние Git. Получить Id, MainWindowTitle, Responding процессов 1cv8, 1cv8c, 1cv8s. Сопоставить подключение с локальной настройкой; заголовок использовать лишь как дополнительный признак. При неоднозначности не закрывать процесс.
2. Перед пакетной операцией штатно закрыть только подтверждённые целевые сеансы через CloseMainWindow() и дождаться завершения. Принудительно не завершать. Не запускать две пакетные операции над одной базой.
3. Окна «Доступ к информационной базе» и «Загрузка конфигурационной информации...» могут быть промежуточными; Responding=False во время загрузки сам по себе не означает сбой. Дождаться основного окна с конечным разумным сроком ожидания; при задержке сообщить состояние, не создавать дубликат.
4. После синхронизации восстановить исходное число и тип сеансов независимо от успеха операции. Явная команда запуска или закрытия задаёт новое целевое состояние.
5. Запуск конфигуратора с хранилищем: run-designer-repository.ps1. Успех скрипта означает передачу параметров хранилища; доступ к самому хранилищу не объявлять проверенным без подтверждения в сеансе.
6. Запуск предприятия: run-enterprise.ps1; проверить фактический тип клиента. Если проект требует тонкий клиент, убедиться, что запущен 1cv8c, а не считать любой 1cv8 успешным результатом.
7. При «Информационная база не обнаружена! Создать новую?» не создавать базу. Закрыть только подтверждённый ошибочный сеанс, уточнить корректность локального подключения и версии платформы.

## Обнови проект

Выгрузить только изменённые объекты текущей конфигурации в src в режиме update, затем обеспечить открытый конфигуратор. Дополнительный вопрос о типе выгрузки не нужен. Получение из хранилища эта команда автоматически не выполняет. Если src/ConfigDumpInfo.xml отсутствует, сообщить, что для первоначальной выгрузки требуется отдельно согласованная полная выгрузка.

```powershell
& '../1c-common/skills/1c-batch/scripts/dump-config.ps1' 'src' 'update'
```

Дождаться завершения; проверить код 0 и сообщение об успешной выгрузке. Получить количество файлов, git status --short, git diff --name-only -- src, git diff --numstat -- src и git diff --check -- src. Сравнить с исходным состоянием. Контрольные количества хранить только в конкретном проекте с датой; не переносить число из другой конфигурации. Отличать изменения содержимого от представления байтов и окончаний строк.

Если выгрузка затрёт незагруженные пользовательские изменения, сначала сохранить их для восстановления или согласовать замену согласно запросу; не терять их молча.

## Обнови конфигурацию

Загрузить сделанные в проекте изменения в тестовую конфигурацию. По diff установить точный состав; по возможности использовать частичную загрузку по контракту load-config.ps1. Не включать несвязанные пользовательские изменения без основания. Учесть, что по умолчанию скрипт обновляет конфигурацию БД; skipdbupdate применять только когда это соответствует поручению.

Не захватывать автоматически объекты хранилища. При блокировке незахваченным объектом сообщить точный объект и восстановить сеансы. Загрузка в тестовую базу не является помещением в рабочее хранилище.

## Запуск и закрытие

«Запусти сеанс»: обеспечить один отвечающий конфигуратор с параметрами хранилища и один тонкий клиент целевой базы, пропуская уже выполненные действия.

Если пользователь явно указал «Запусти сеанс толстый», запускать толстый клиент 1cv8 вместо тонкого 1cv8c. Явно указанный тип клиента имеет приоритет; при восстановлении после синхронизации сохранять фактический исходный тип клиента.

«Запусти конфигуратор и подключись к хранилищу»: обеспечить только запрошенный конфигуратор. «Закрыть сеансы»: штатно закрыть подтверждённые целевые сеансы. Эти команды разрешают необходимые действия с сеансами; повторно разрешение на них не запрашивать.

## Отчёт

Указать результат пакетной команды, изменения src и итоговое состояние сеансов. Различать успешный запуск процесса, доступность базы, подключение к хранилищу и проверку бизнес-сценария. Загрузку и выгрузку не выполнять только ради проверки данного навыка.
