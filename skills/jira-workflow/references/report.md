# Отчёт, время и статус

Публиковать только по явному поручению пользователя. Общий запрос анализа или создание навыка не является таким поручением.

## Подготовка

Определить ключ задачи, проверить подключение по [connection.md](connection.md), получить каталог MCP tools/list и прочитать задачу, существующие worklog и комментарии. Все операции выполнять через tools/call по фактическим inputSchema; если нужного инструмента нет, сообщить ограничение. Сверить Memory Bank с фактическими изменениями и проверками. Не приписывать платформенные тесты, загрузку базы, коммит или перенос объектов, если они не выполнялись.

Спросить количество часов, если оно ещё не указано для данного отчёта. Уточнить только неоднозначность: указанное число означает добавляемое время или итог. Не оценивать время самостоятельно.

## Worklog

Добавлять отдельную запись на согласованное дополнительное время: Jira прибавит её к существующему итогу. Не передавать в новую запись сумму старого и нового времени и не переписывать чужие записи.

Вызвать MCP-инструмент добавления worklog из каталога. По его inputSchema передать ключ задачи и следующие данные (названия полей и формат определяются схемой):
- длительность — согласованное добавляемое время в секундах, положительное целое число; если инструмент принимает строку длительности, преобразовать время в его формат без округления;
- описание — краткий фактический перечень выполненных действий;
- начало — дата и время работы с часовым поясом, если они известны или явно указаны; не выдумывать историческую дату.

Сформировать JSON через ConvertTo-Json и отправить в UTF-8 (Content-Type: application/json; charset=utf-8). До записи сохранить существующие ID. После записи проверить ID и добавленную длительность. При таймауте проверить записи по исполнителю, времени и тексту перед повтором: результат записывающего tools/call может уже существовать.

## Комментарий с объектами

Для команды «Сделай отчёт» добавлять комментарий только если изменялись объекты конфигурации 1С. Изменение правил, навыков и документации само по себе такого комментария не требует. Отдельное явное поручение написать комментарий выполняется по его содержанию.

По diff определить уникальные объекты для переноса в рабочую конфигурацию, например:
- ОбщийМодуль.ИмяМодуля
- Справочник.ИмяСправочника

Не включать один ConfigDumpInfo.xml в перечень бизнес-объектов. Не утверждать, что объекты уже перенесены.

Вызвать MCP-инструмент добавления комментария с ключом задачи и текстом по его inputSchema. Перед созданием проверить, не опубликован ли этот же отчёт ранее. После записи проверить результат.

## Статус

Менять статус, только если пользователь его указал. Получить доступные переходы MCP-инструментом, выбрать переход по фактическому целевому статусу и его ID; не использовать постоянные ID из другой задачи. Учесть обязательные поля перехода и схему инструмента.

Вызвать MCP-инструмент перехода с фактическим ID и необходимыми согласованными полями по его inputSchema. Если переход недоступен или нужны неизвестные обязательные данные, сообщить ограничение. Проверить итоговый статус повторным чтением задачи через MCP.

Не скрывать частичный успех: отдельно сообщить выполненный worklog, комментарий и переход. При сбое повторять только невыполненную часть после проверки.
