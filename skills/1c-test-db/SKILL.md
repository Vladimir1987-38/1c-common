# Запросы и диагностика тестовой базы 1С

Перед началом новой задачи выполнить [правило перехода к новой задаче](../../rules/workflow.md#переход-к-новой-задаче): обязательно спросить «Материалы по старой задаче переносить в архив или очищать», дождаться выбора и обработать материалы предыдущей задачи до выполнения этого навыка. Уже сделанный выбор для этого перехода повторно не запрашивать; при продолжении текущей задачи переход не выполнять. При выборе архива обязательно перенести прежние `doc/MEMORY_BANK.md` и `doc/PROMT.md` в папку предыдущей задачи и создать вместо них новые файлы с теми же именами в `doc` для новой задачи.

Общие правила: [workflow.md](../../rules/workflow.md). Работать из корня целевого проекта; прочитать его doc/AGENTS.md и текущую задачу. Создание, выбор или вызов этого навыка сами по себе не разрешают подключение.

## Сначала цель и разрешение

1. Определить тестовую базу по текущей настройке проекта или явному указанию пользователя. Слово test в имени, прежний успех соединения и реквизиты из журналов не доказывают, что база тестовая. Рабочую базу не использовать как запасной вариант.
2. Различать адрес сервера 1С и имя ИБ, адрес экземпляра SQL Server и имя SQL-базы, путь файловой ИБ. Эти значения не взаимозаменяемы. Настройка .1c-devbase обычно содержит реквизиты 1С, а не SQL. Недостающие адреса уточнить у пользователя до подключения, не искать их пробными соединениями.
3. Перед Open/Connect, проверкой прав, версий и доступности получить явное разрешение пользователя: конкретная тестовая база, прямой SQL или через 1С, цель, чтение либо перечисленные изменения. Пример: «Разрешаете прямое подключение к SQL Server SERVER\\INSTANCE, базе BASE_TEST, для SELECT по обращениям в рамках текущей задачи?» Если способ не разрешён, не подменять им согласованный способ.
4. Если такое разрешение уже явно дано в текущей задаче, работать в его пределах без повторных вопросов для каждого запроса. «Продолжи», «разберись» и общее поручение на анализ разрешением не являются. При смене базы, способа или расширении действий запросить новое разрешение.
5. Пока разрешения нет, готовить запросы и изучать файлы локально. Не запускать скрипт, который попутно проверит соединение. Автоматическое одобрение инструмента и Windows-аутентификация не заменяют согласия пользователя.

## Выбор способа

| Задача | Способ |
|---|---|
| Физические таблицы, индексы, SQL-планы, агрегаты технологического журнала | Прямое чтение SQL Server: [direct-sql.md](references/direct-sql.md) |
| Запросы по именам метаданных, права 1С, виртуальные таблицы и воспроизведение бизнес-логики | Платформа 1С: [through-1c.md](references/through-1c.md) |
| Загрузка/выгрузка конфигурации, запуск/закрытие сеансов | [1c-project-sync](../1c-project-sync/SKILL.md) и [1c-batch](../1c-batch/SKILL.md) |

Прямой SQL не выполняет RLS и обработчики объектов 1С. Для проверки видимости пользователю и поведения при записи использовать 1С. Этот навык не предназначен для прямого изменения физических таблиц 1С SQL-командами. Не объявлять результат SQL проверкой бизнес-сценария.

## Настройки и секреты

Не читать и не выводить содержимое .1c-devbase.ps1/.bat, логины, пароли, токены и полные строки соединений. Применять настройки по штатному алгоритму 1c-batch. Не запускать непроверенный локальный файл настроек ради получения имени базы до разрешения: если нет гарантированного способа прочитать только безопасную цель без подключения и выполнения побочных действий, уточнить цель у пользователя.

Не создавать общий список баз/паролей в навыке. Не переносить адрес рабочей базы из прошлого расследования. SQL-реквизиты хранятся в локальном .sql-devbase.psd1 выбранного проекта (исключён из Git); формат и безопасное чтение описаны в [direct-sql.md](references/direct-sql.md). Шаблон для нового проекта: [sql-devbase.example.psd1](assets/sql-devbase.example.psd1). Windows-аутентификацию использовать только после разрешения. Полученное ранее разрешение не сохранять в навыке как постоянное.

## Выполнение и результат

- До соединения подготовить минимальный набор запросов с отборами и ограничением результата; объяснить планируемые изменения отдельно от чтения.
- После разрешённого соединения сверить фактическую базу с ожидаемой перед запросами к данным. При несовпадении закрыть соединение и остановиться, не переключаться автоматически на другую базу.
- Начинать с ключей, количества, дат и размеров; тексты, двоичные поля и вложения читать только для конкретных записей, когда это необходимо. Не выгружать таблицы целиком ради поиска одной записи.
- Ограничить время соединения и команд. При отказе доступа, несовпадении цели или таймауте остановить текущую попытку; не перебирать базы, учётные записи и способы входа. Повтор допустим после конкретного устранения причины в рамках того же разрешения.
- Закрыть созданное соединение/сеанс в finally, в том числе при ошибке. Не закрывать чужие сеансы и не завершать процессы кластера.
- В отчёте назвать способ подключения, базу, фактически выполненные действия, ограничения и изменённые данные, если они были отдельно разрешены. Отличать результаты SQL от проверки платформой 1С. В локальных доказательствах сохранять запросы и минимальную сводку без секретов; не делать из старого диагностического скрипта разрешение на новый запуск.

## Проверка самого навыка

Без разрешения на конкретную базу выполнять только проверку Markdown, ссылок и синтаксиса подготовленных команд. Не выполнять Open, Connect, SELECT 1, запуск сеанса или конфигуратора ради проверки навыка. Реальное подключение и функциональная проверка — отдельная разрешённая пользователем операция.
