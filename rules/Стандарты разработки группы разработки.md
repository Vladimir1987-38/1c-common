# Стандарты разработки группы разработки

Обязательны для всех подключённых проектов наравне с [общими стандартами 1С](1c-development.md). Перед каждым новым этапом изменения кода читать актуальную редакцию. Перед завершением проверять изменённые фрагменты по всем применимым правилам ниже.

Примеры иллюстрируют отдельные требования к оформлению и могут быть неполными фрагментами. Предметные значения и формулы из примеров не переносить в рабочий код без требований задачи. Пометки «НЕПРАВИЛЬНО» показывают варианты, которых следует избегать.

## 1. Выравнивание общих по смыслу строк кода, находящихся в одном блоке.

Выравнивание делать табуляцией, а не пробелом.

Пример:

~~~bsl
ДатаСобытия			= ОбщегоНазначения._ТекущаяДатаСеанса();
Пакет				= ДанныеЛогаНазначения();
Очередь				= Пакет[Пакет.ВГраница() - 1].Выгрузить();
Слоты				= Пакет[Пакет.ВГраница()].Выбрать();
НазначаемаяЗадача	= ТаблицаЗадач[0];
~~~

## 2. Отступ между блоками кода, общих по смыслу

Пример:

~~~bsl
ДатаСобытия			= ОбщегоНазначения._ТекущаяДатаСеанса();
Пакет				= ДанныеЛогаНазначения();
Очередь				= Пакет[Пакет.ВГраница() - 1].Выгрузить();
Слоты				= Пакет[Пакет.ВГраница()].Выбрать();
НазначаемаяЗадача = ТаблицаЗадач[0];

Отбор = Новый Структура("Ссылка,ЗаказГруппы",
				НазначаемаяЗадача.Задача, НазначаемаяЗадача.Заказ);
СтрокиНазначения = Очередь.НайтиСтроки(Отбор);

Если СтрокиНазначения.Количество() = 0 Тогда
	ВызватьИсключение "Назначаемая задача отсутствует в очереди на момент сбора лога";
КонецЕсли;

ДанныеЗадачи = СтрокиНазначения[0];
Контекст = Новый Структура("Timestamp1c,TaskId,НазначаемаяЗадача",
			Формат(ДатаСобытия, "ДФ='yyyy-MM-dd HH:mm:ss.000'"),
			Строка(НазначаемаяЗадача.Задача.УникальныйИдентификатор()), НомерЗадачиДляЛога(ДанныеЗадачи.НомерЗадачи));

~~~

## 3. Отступы между логическими выражениями

Пример:

~~~bsl
Сообщение = НовоеСообщениеЛогаНазначения(Контекст, "ГрейлогНазначемаяЗадача");
Сообщение.Вставить("ГлавнаяЗадача"		, НомерЗадачиДляЛога(ДанныеЗадачи.ГлавнаяЗадача));
Сообщение.Вставить("Заказ"				, ДанныеЗадачи.Заказ);
Сообщение.Вставить("ЗаказГлавнойЗадачи"	, ДанныеЗадачи.ЗаказГлавнойЗадачи);

Если СтрокиНазначения.Количество() > 1 Тогда

	Сообщение.ГлавнаяЗадача = Null;
	Сообщение.ЗаказГлавнойЗадачи = Null;

КонецЕсли;
~~~

## 10. Описание процедур и функций в области ПрограммныйИнтерфейс

Описания по этому пункту создавать **только в области ПрограммныйИнтерфейс**. В остальных областях не добавлять такие описания к методам; содержательные пояснения внутри алгоритмов сохранять. Признак Экспорт сам по себе не является основанием для описания вне этой области.

Описывать назначение и контракт метода: что получает вызывающий код, какие значения допускаются и что означает отказ. Начинать описание с глагола: «Возвращает», «Проверяет», «Записывает». Не пересказывать имя метода и очевидные строки реализации.

- В области ПрограммныйИнтерфейс описание обязательно для всех добавленных и изменённых в рамках задачи процедур и функций, а не только для методов, отдельно указанных пользователем. Служебные методы и обработчики в других областях под это требование не подпадают.
- Размещать описание перед объявлением метода, в модуле формы — перед директивой контекста. Пустые строки внутри описания оформлять как строку с двумя косыми чертами.
- В разделе «Параметры:» перечислять точные имена, типы и назначение параметров. Указывать допустимые пустые значения, значения по умолчанию и изменение переданного параметра, когда это существенно. Звёздочка обозначает вложенные свойства, а не сами параметры.
- Для функции добавлять «Возвращаемое значение:» с типом и смыслом результата; для процедуры этот раздел не нужен. Явно описывать Ложь, пустую строку, пустую таблицу и Неопределено, если они предусмотрены контрактом. Для разных типов результата перечислять варианты отдельными строками с дефисом.
- Для структуры и таблицы значений раскрывать используемые свойства/колонки: звёздочка, имя, тип, назначение. Для уже описанного контракта допустима точная ссылка «см. Модуль.Метод»; ссылка должна вести к актуальному описанию.
- Указывать существенные побочные действия, условия отказа и исключения. Не обещать в комментарии проверок или гарантий, которых нет в коде. При изменении контракта актуализировать описание.
- Не добавлять пустые разделы и бессодержательные комментарии. При поручении изменить только комментарии сохранять сигнатуры, директивы контекста и весь исполняемый код.

Пример полного описания функции поиска (контракт из задачи FUS-288):

~~~bsl
// Возвращает локальные карты кассиров и администраторов по началу ФИО владельца.
// Исключает удалённые карты и владельцев, а также карты, не принадлежащие сотрудникам.
// Не подтверждает право входа: перед входом требуется отдельная проверка выбранной карты.
//
// Параметры:
//  ФИО - Строка - начало ФИО без учёта пробелов по краям.
//   Пустое значение возвращает таблицу без строк.
//
// Возвращаемое значение:
//  ТаблицаЗначений - найденные карты, упорядоченные по ФИО владельца:
//   * ИнформационнаяКарта - СправочникСсылка.ИнформационныеКарты - найденная карта.
//   * ВладелецКарты - СправочникСсылка.ВладельцыИнформационныхКарт - владелец карты.
//   * ДатаРождения - Дата - дата рождения владельца.
//   * СостояниеКарты - ПеречислениеСсылка.СостоянияИнформационныхКарт - роль карты.
//   * ВидКарты - Строка - представление состояния карты для показа пользователю.
//
// Пример:
//  НайденныеКарты = Справочники.ИнформационныеКарты.КартыКассировДляАварийногоВхода("Иванов");
//  // Таблица содержит подходящие локальные карты или не содержит строк.
Функция КартыКассировДляАварийногоВхода(ФИО) Экспорт
    // Реализация поиска.
КонецФункции
~~~

Если результат имеет несколько типов, оформлять его, например, так:

~~~bsl
// Возвращаемое значение:
//  - ПеречислениеСсылка.СостоянияИнформационныхКарт - проверенная роль кассира или администратора.
//  - Неопределено - аварийный режим выключен, карта недоступна либо её владелец или роль изменились.
~~~

Основание: стандарты 1С [«Описание процедур и функций»](https://its.1c.ru/db/content/v8std/src/400/100/i8100453.htm) и [«Структуры и таблицы значений в качестве параметров процедур и функций»](https://its.1c.ru/db/content/v8std/src/400/100/i8100641.htm).

## 11. Запрет на имена переменных, совпадающие с системными именами 1С

Запрещено использовать системные имена 1С для собственных переменных, параметров процедур и функций и переменных цикла. Не использовать имена `Параметры`, `Задачи`, `Документы`, `Справочники`, `РегистрыСведений` и другие имена свойств глобального контекста, а также системных свойств текущей формы или объекта. Перечень примеров не является исчерпывающим; учитывать контекст исполнения модуля и доступные в нем системные имена. Запрет действует независимо от регистра букв и даже если платформа допускает перекрытие имени в отдельном контексте.

Выбирать конкретное имя по назначению значения: `ПараметрыОтображения`, `ОформлениеЗоны`, `СписокЗадач`, `ДанныеЗадачи`, `СписокДокументов`. Запрет относится к объявлению собственных имен и присваиванию им значений. Штатные обращения к платформе, например `Документы.Задача.ПолучитьСсылку(...)`, сохраняются.

Перед добавлением или переименованием переменной проверить, не совпадает ли ее имя со свойством глобального контекста или текущего объекта/формы. Перед завершением доработки обязательно повторно проверить все введенные и измененные имена, включая параметры и переменные циклов. При сомнении проверить имя в синтакс-помощнике соответствующей версии платформы или выбрать однозначное предметное имя. Успешный разбор BSL внешним парсером не подтверждает отсутствие таких конфликтов и не заменяет эту проверку.

НЕПРАВИЛЬНО:

~~~bsl
Параметры = Новый Структура;
Для Каждого Задачи Из МассивыЗадач Цикл
Документы = Новый Массив;
~~~

ПРАВИЛЬНО:

~~~bsl
ПараметрыОтображения = Новый Структура;
Для Каждого СписокЗадач Из МассивыЗадач Цикл
СписокДокументов = Новый Массив;
~~~

## 12. Только стандартные области модулей 1С

При добавлении и переносе кода использовать только области, предусмотренные стандартом 1С для соответствующего типа модуля. Собственные названия областей запрещены, в том числе вложенные области и названия по теме доработки или номеру задачи: например, СлужебныеПроцедурыАварийногоВхода или СлужебныеПроцедурыМенюОшибкиАвторизации.

- Сначала найти подходящую стандартную область в текущем модуле и поместить код в неё. Существующую область не дублировать.
- Если нужной стандартной области нет, создать её со стандартным названием и в предусмотренном стандартом месте модуля.
- Выбирать область по назначению кода: например, СлужебныеПроцедурыИФункции для служебных методов, ОбработчикиКомандФормы для команд формы, ОбработчикиСобытийФормы для событий формы, ПрограммныйИнтерфейс для предусмотренного внешнего интерфейса. Признак Экспорт сам по себе не делает внутренний callback публичным API.
- Свои ранее добавленные нестандартные области исправлять переносом кода в соответствующие стандартные области и удалением лишних директив. Сохранять контекст исполнения, сигнатуры, тела методов и маркировку задачи.
- Перед завершением проверить названия, назначение, отсутствие дубликатов стандартных областей и парность #Область / #КонецОбласти во всех изменённых модулях.

Основание: стандарт 1С «Структура модуля», указанный в [стандартах разработки 1С](1c-development.md#оформление-bsl). Пользовательское требование запрещает вводить собственные области.

## 13. Не использовать венгерскую нотацию

Имена переменных и параметров должны отражать назначение и смысл данных, а не их тип или конкретную реализацию коллекции. Не включать в имя префиксы и другие обозначения типа: например, МассивКонстант, СтруктураНастроек, СтрокаТелефона. Имя не должно требовать переименования только из-за замены массива другой подходящей коллекцией.

Использовать предметные имена: КоллекцияКонстант, ИменаОтключаемыхКонстант, НастройкиОбмена, НомерТелефона. Слово Коллекция допустимо как общее обозначение набора без привязки к определённому типу коллекции. Тип указывать в описании параметра или возвращаемого значения, когда это требуется стандартом документирования, а не кодировать в имени.

НЕПРАВИЛЬНО:

~~~bsl
МассивКонстант = Новый Массив;
МассивКонстант.Добавить("ПрограммаЛояльностиДоступна");
~~~

ПРАВИЛЬНО:

~~~bsl
КоллекцияКонстант = Новый Массив;
КоллекцияКонстант.Добавить("ПрограммаЛояльностиДоступна");
~~~

Допустимый вариант по назначению: ИменаОтключаемыхКонстант. При выборе имени также соблюдать запрет на совпадение с системными именами 1С.

Применять правило при добавлении и изменении имён. Само обновление стандарта не является поручением массово переименовывать существующий код.

## Обязательно руководствоваться стандартами 1С
